## Executive Summary

DISHA 6.6 is the current public version of the DISHA Intelligence Architecture. It is presented as an evidence-first architecture for converting signals into source-linked records, preserving those records as memory, and supporting accountable reasoning across public-interest research, cyber evidence, digital governance and constitutional accountability.

DISHA 6.6 has four public duties:

1. Keep claims attached to source records.
2. Separate fact, allegation, unresolved question and analysis.
3. Preserve institutional memory so that evidence is not lost across time.
4. Apply policy and constitutional guards before high-risk conclusions or actions.

The release is therefore not only a technical note. It is also a source discipline note. Every major claim must point back to a canonical page, document, citation file, GitHub repository, ORCID identity, Wikidata entity or public institutional source.

## Architecture Overview

DISHA 6.6 can be explained as a record-to-reasoning architecture. It begins with a signal and ends with a bounded, source-aware output. The public architecture page describes the chain as signal, evidence, memory, intelligence and accountability.

### Layer 1: Signal Intake

A signal is any input that may require examination. It can be a document, public record, court filing, agency reply, cyber indicator, media report, image, dataset, source PDF, official communication or unresolved contradiction. DISHA does not treat a signal as truth. It treats the signal as something that must be classified.

### Layer 2: Evidence Classification

Evidence classification prevents overclaiming. A record can be classified as official record, corroborated record, documented allegation, DISHA assessment or unresolved question. This is essential for public trust because readers must know whether they are reading a primary source, a filed claim, an analytical inference or a pending question.

### Layer 3: Memory

The memory layer preserves records across time. In public-interest work, memory is not only storage. It is continuity. A grievance, filing, report, audit line or institutional reply may become meaningful only when compared against a later reply, later silence or later contradiction.

### Layer 4: Reasoning

The reasoning layer connects records, duties, institutions, timelines and public consequences. It should remain bounded by the evidence classification. A DISHA inference must never be presented as a government finding, court finding or final adjudication unless a competent authority has actually recorded that finding.

### Layer 5: Constitutional and Policy Guards

The guard layer limits what the architecture can say or do. It requires public-source grounding, privacy protection, human review, no-first-use discipline, legal boundary language and a clear distinction between action, recommendation and record preservation.

## Identity Sovereignty Module

The identity sovereignty module is the part of DISHA 6.6 that examines how identity is created, controlled, verified, used, misused and recovered across digital systems. In public copy, use the phrase carefully. Do not present it as enacted law unless a legal source supports that claim.

The module asks:

- Who controls the identity record?
- Which system stores the data?
- Can the citizen inspect, correct or challenge the record?
- Is the data held in a lawful and sovereign environment?
- Is there a human officer accountable for the outcome?
- Can the record be preserved for evidence?
- Can harm be traced after the event?

## Safety and Constitutional Guards

DISHA 6.6 should use guardrails that are understandable to technical and legal readers.

### Evidence guard

No conclusion should appear without a source path. If the page cannot provide a source, the sentence must be marked `[VERIFY REQUIRED]` or rewritten as a question.

### Privacy guard

Personal addresses, phone numbers, private identifiers, signatures and non-public filing details should not be exposed on public pages unless the user has expressly authorised publication and the record is legally safe to publish.

### Legal-boundary guard

Use terms like "filed claim", "author's analysis", "documented allegation", "unresolved question", "court-facing record" and "public source" where appropriate. Avoid presenting unresolved allegations as adjudicated facts.

### No-first-use guard

DISHA public copy should describe defensive, evidence-preserving and source-review functions before any action-oriented language. If a page discusses active response, it should explain the policy gate first.

### Human review guard

Outputs that could affect a person, institution or legal conclusion should require human review. This matters for public trust, AI safety and constitutional accountability.
